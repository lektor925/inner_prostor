# Handoff: Справочник номенклатуры 1С:УПП на Django

## Контекст проекта
Владимир строит внутренний read-only справочник номенклатуры на Django для конструкторов на производственном предприятии (ледовые арены, ООО «ПРОСТОР-Л» — см. проект УПП). Проблема: конструкторы не умеют работать в запутанном интерфейсе 1С:УПП и создают дубли номенклатуры вместо использования существующих позиций. Склад и ОМТС уже работают напрямую в 1С — им отдельный интерфейс не нужен, единственная целевая аудитория сайта — конструкторы.

Связанные проекты в памяти: `[[nsi-studio]]` (отдельный инструмент для чистки/миграции НСИ, там веб-UI сознательно исключён из объёма), `[[upp-implementation]]` (общий проект внедрения УПП).

## Принятые архитектурные решения

- **Стек**: Django + PostgreSQL. Postgres выбран специально ради `pg_trgm` (нечёткий триграммный поиск) — критично для отлова похожих/дублирующих названий номенклатуры, которые пишут по-разному. MySQL для этой задачи хуже (нет нативного триграммного поиска).
- **Масштаб**: ~30-40 тыс. позиций номенклатуры — комфортно для Django/Postgres при наличии индексов (обычные + GIN для pg_trgm), не узкое место.
- **Синхронизация**: периодическая (не live), в одну сторону 1С → Django:
  - 1С регламентное задание → обработка выгружает номенклатуру (+ остатки) в файл (CSV/JSON/XML) на сетевой ресурс
  - Django cron/management-команда (`import_1c`) забирает файл и делает `update_or_create` по коду позиции (`code_1c`)
  - Расписания разные: характеристики номенклатуры — редко (раз в сутки), остатки — чаще (раз в несколько часов), т.к. это разные по волатильности данные
- **Роли**: только конструкторы (поиск/просмотр/заявки) + Владимир как единая точка одобрения новых позиций (админка). Никакой прямой записи из Django в 1С.
- **Замыкание цикла (ключевое для решения проблемы дублей)**: конструктор ищет → не находит → оставляет заявку на новую позицию через сайт (не создаёт сам в 1С) → Владимир одобряет и заводит позицию в УПП по единым правилам → она появляется в справочнике при следующей синхронизации.

## Новая фича в разработке: остатки на складе
Владимир хочет добавить в выгрузку остатки на складе, чтобы конструкторы могли закладывать в разработку то, что залежалось на складе (не для целей закупки/резервирования, а как "используй, что есть"). Решения:
- Порог отсечки (обсуждалось >1000 шт.) и фильтр по складам делать **на стороне Django**, настраиваемым, а не жёстко фильтровать при выгрузке из 1С — гибче, разный порог для разных типов номенклатуры (крепёж vs метраж vs лист).
- Периодическая синхронизация остатков достаточна (не нужен реалтайм) — расхождение в часы не критично для этой задачи, в отличие от закупок.
- Открытый вопрос: остатки нужны суммарно или разрезом по складам — не решено.
- Учитывать резерв (`остаток - зарезервировано`), иначе конструктор увидит цифру, которая уже занята другим заказом.

## Открытый вопрос — требует уточнения в следующей сессии
**1С: файловая база или клиент-серверная (SQL Server)?** Это критично для надёжности регламентных заданий:
- Клиент-серверная — штатный сервер регламентных заданий работает без проблем, задание выполняется на сервере независимо от RDP-сессии Владимира.
- Файловая — регламентные задания менее надёжны, может понадобиться отдельный агент/внешний планировщик (Windows Task Scheduler, запускающий `1cv8.exe /C...`).

Известно: база 1С на локальном сервере, доступ к нему — через RDP. Уточнить также: сервер 1С и будущий сервер Django — одна машина или разные (влияет на способ передачи файла выгрузки — общая сетевая папка/SMB/FTP).

## Ещё не решено / горизонт
- Полный пайплайн деплоя: Gunicorn + Nginx + systemd + Postgres на локальном сервере (Claude уже согласился помочь, когда дойдёт до этой стадии).
- Локальный DNS, чтобы конструкторы заходили по внутреннему домену, а не IP. Варианты обсуждены: AD DNS (если есть домен), статические записи на роутере, `dnsmasq` (рекомендован как практичный вариант, если нет штатного админа сети), либо hosts-файлы (не масштабируется).
- Структура моделей Django (Nomenclature, Request/заявка, SyncLog) — предложена, но код ещё не написан.
- Пример обработки в 1С для выгрузки JSON — не написан.
